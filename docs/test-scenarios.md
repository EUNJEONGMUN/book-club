# 단일 부글부글 회귀 검증

아래 회귀 테스트 명령은 로컬 환경에서 실행한다. 브라우저 회귀 테스트는 조회를 수행한다. DB 쓰기 권한 테스트는 변경을 롤백하고, 여러 연결을 사용하는 동시 등록 테스트는 커밋한 임시 데이터를 검증 뒤 정리한다.

| 영역 | 확인 내용 | 검증 방법 |
|---|---|---|
| 진입 | 기존 로그인 유지, 그룹 선택 없이 홈 진입 | 단위·로컬 화면 |
| 가입 상태 | 미가입 → 안내, pending → 대기, member/admin → 이용 | 단위·Postgres 권한 시험 |
| 기존 일정 | 목록·상세·발제·참석·한줄 평 조회 | 화면·기록 비교 |
| 멤버/설정 | 멤버·이력·소개·프로필·관리자 기능 조회 | 화면 |
| 권한 | 본인/호스트/관리자 역할별 허용·차단 | 롤백 통합 시험 |
| 가입/관리 | 신청 중복·초대 만료·승인·거절·탈퇴·이양 | 롤백 통합 시험 |
| 발제 파일 | 호스트만 업로드·수정·삭제, 다른 경로로 이동 차단 | 롤백 통합 시험 |
| 발제 질문 | 동시 단건·일괄 등록 시 순번 고유성과 일괄 입력 순서, 수정·삭제 0행 응답 | 단위·로컬 DB 통합 |
| PDF 추출·저장 | 현재 첨부 경로만 허용, 실패 후 버튼 복구 및 질문 후보 보존 | 단위·컴포넌트 테스트 |
| 한국 날짜 | 자정과 연도 경계의 D-Day 계산 | 단위 테스트 |
| 과거 주소 | 부글부글의 기존 주소는 새 주소로, 다른 ID는 404 | 단위·화면 |
| 데이터 보존 | 현재·보관 테이블, 계정 인증 정보, Storage 메타데이터 비교 | 보존 비교 스크립트 |

```bash
node scripts/check-local-records.mjs snapshot .local-backups/회귀검증-전.json
pnpm test
pnpm test:integration
pnpm test:e2e
node scripts/check-local-records.mjs compare .local-backups/회귀검증-전.json
```

화면 테스트는 로컬 시드 계정과 기존 샘플 일정이 있는 환경을 사용한다. 로그인 시각 등 인증 시스템이 정상적으로 갱신하는 값은 보존 비교에서 제외하고, 계정 ID·이메일·암호 해시는 비교한다. 과거 테스트의 DB 전체 삭제 방식은 사용하지 않는다.

## 운영 배포 확인 기록

| 변경 | 확인한 내용 |
| --- | --- |
| Sentry 터널 | 로그아웃 상태의 `/monitoring` 요청이 로그인으로 이동하지 않고 Sentry까지 전달됐다. 운영에서는 의도적으로 잘못된 요청의 HTTP 400 응답을, 정상 이벤트 전달은 로컬 수신기에서 확인했다. [PR #83](https://github.com/EUNJEONGMUN/book-club/pull/83) |
| 초대 링크와 질문 순번 | 기존 운영 DB에 마이그레이션을 먼저 적용했다. 기존 질문 67개의 내용을 대조하고 운영 DB의 단건·일괄 등록을 롤백 테스트로 확인했다. 관리자 초대 링크의 표시·복사·만료 시각은 로컬 Chromium에서 확인했다. [PR #84](https://github.com/EUNJEONGMUN/book-club/pull/84) |
| 발제 파일 | 운영 브라우저에서 테스트 PDF 업로드·교체, 기존 Storage 객체 정리, Gemini 추출과 질문 저장을 확인했다. 교체 실패 시 기존 파일 보존은 로컬 DB·Storage에서 실패 응답을 주입해 검증했다. [PR #85](https://github.com/EUNJEONGMUN/book-club/pull/85) |
| 한국 날짜와 접근성 | 운영 Chromium에서 서울·로스앤젤레스 시간대의 날짜 표시가 일치했다. Tab으로 폼의 다섯 입력에 이동하고, Enter로 등록 화면과 수정 취소 링크를 실행했다. 날짜 입력과 오류 설명의 연결을 확인했다. [PR #86](https://github.com/EUNJEONGMUN/book-club/pull/86) |

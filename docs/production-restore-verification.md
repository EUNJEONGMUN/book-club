# 운영 백업의 격리 복원·보존 검증 결과

2026-11-08 검증 완료. **226개 검사 통과.** 운영 DB에 접속하지 않고, 외부 네트워크·공개 포트가 없는 임시 로컬 PostgreSQL 컨테이너에서 수행했다.

후속 실제 Auth·파일 HTTP·브라우저 검증도 로컬에서 완료했다. 해당 결과와 남은 Google 외부 인증 범위는 `docs/local-service-flow-verification.md`를 참조한다. 아래는 최초 격리 복원 단계의 결과다.

단순 건수만 비교하지 않았다. 아카이브에서 독립적으로 추출한 **49개 테이블 데이터 블록의 전체 COPY 레코드**와 복원 DB에서 다시 읽은 전체 레코드를 순서와 무관하게 대조했다. 아카이브에 포함된 시퀀스 위치 2개도 일치했다. 오류를 무시하거나 테이블을 제외하지 않고 전체 아카이브를 복원했다.

접근 권한은 원본 아카이브의 정책 정의와 복원 DB를 다시 덤프한 정책 정의를 비교했다. 조건식 전체와 RLS 활성화·강제 설정이 일치했다. 이전 읽기 전용 조회의 46개 public/storage 정책 이름·대상 역할·명령도 일치했다. API가 역할 배열을 문자열로 반환하는 차이와 조회 search_path에 따른 조건식 표시 차이는 구분했고, 조건식 비교는 두 덤프의 같은 표현으로 엄격하게 수행했다.

파일 14개는 기존 로컬 저장소에 업로드하지 않고 격리 컨테이너의 별도 경로로 복원했다. DB의 객체 ID·버킷·원래 경로와 연결해 복원 바이트의 해시를 다시 확인했다. 일정에 연결된 발제 파일 6개뿐 아니라 보관된 나머지 파일도 포함한다.

## 단일 모임 전환 예행연습

검증된 복원 DB를 새 DB로 다시 복제하고, 그 두 번째 복원본에만 02 → 03 → 04 SQL을 적용했다. 스키마 변경은 격리 컨테이너의 `supabase_admin` 역할로 수행했다.

- 원래 모임·멤버·초대 테이블 전체가 `legacy_multiclub`에 동일하게 보관됐다.
- 변경 전 프로필·일정의 전체 행도 보관본과 일치했다. 서비스 테이블에서는 의도적으로 제거한 그룹 필드 외의 모든 필드가 일치했다.
- 새 모임 설정·멤버·초대에 원래 ID·역할·시각·토큰을 그대로 옮겼다.
- 질문·참석·평과 모든 Auth/Storage 테이블의 전체 레코드가 전환 전후 일치했다.
- 기준으로 남겨둔 첫 번째 복원 DB도 전환 예행연습 후 전체 레코드가 동일했다.
- 실제 사용 중인 로컬 DB의 현재·보관 17개 테이블을 전후 비교해 기존 기록·계정 식별·인증 정보가 동일한 것을 확인했다.

검증에 생성한 컨테이너와 임시 볼륨은 정리했다. 사용 중인 로컬 DB와 원래 백업은 유지했다.

## 검증 범위와 남은 조건

이번 결과는 DB 아카이브의 실제 복원과 레코드·파일·전환 데이터 보존에 대한 검증이다. Auth/OAuth 서비스와 Storage HTTP API를 시작하거나 실제 회원으로 로그인하지 않았다. 계정 인증 정보가 보존된 것과 실제 서비스 로그인 흐름 검증은 구분한다.

`pg_dump`에는 클러스터 역할이 없으므로, 격리 환경의 역할 초기화에는 비밀번호를 제외한 기존 로컬 역할 정의를 사용했다. 운영의 관리자 접속 역할·소유권·실행 권한에 대한 최종 확인은 남아 있다. 운영 역할이나 비밀번호는 수정하지 않았다.

DB 아카이브와 파일 복사본은 운영 사용 중 서로 다른 시점에 생성됐다. 이번 대조에서는 앱 레코드·파일 메타데이터와 계정 식별·인증 정보가 일치했다. **실제 운영 전환 시에는 쓰기를 중단한 뒤 DB와 파일을 다시 백업·검증해야 한다.** 배포 환경 분리와 외부 Auth/REST/RPC/Storage 쓰기 차단도 아직 운영에 적용하지 않았다.

## 재현 명령

```bash
python3 -B scripts/verify-production-restore.py \
  --backup .local-backups/production-dump-20261108T052113760121Z \
  --records .local-backups/production-readonly-20261108T045110487853Z
```

도구는 고정된 로컬 컨테이너에서 이미지·비밀번호 없는 역할 정의·보존 비교 기준만 읽고, `--pull never --network none`으로 새 검증 컨테이너를 생성한다. 운영 접속 URL이나 비밀번호를 받지 않는다. 실패 시 진단 로그는 비공개 백업 폴더에 저장하고 생성한 검증 컨테이너만 정리한다. 성공 보고서는 기존 로컬 DB와 원본 백업의 보존 확인까지 끝난 후에만 생성한다.

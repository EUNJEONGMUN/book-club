# 로컬 실제 로그인·파일 다운로드 검증 — 2026-11-08

**18개 서비스/브라우저 흐름 검사와 92개 보존 검사 통과.** 기존 운영 백업을 별도 로컬 DB에 복원·전환한 뒤 실제 Supabase Auth·PostgREST·Storage API와 현재 앱을 연결해 확인했다.

운영 DB에 연결하지 않았고 현재 사용 중인 로컬 DB도 수정하지 않았다. 기존 계정의 비밀번호를 변경하지 않고, 새 복원본에만 관리자·멤버·승인 대기·미가입 시험 계정을 만들었다. 로그인 응답이나 사용자 화면을 가짜 데이터로 대체하지 않았다.

## 실제 확인한 흐름

| 항목 | 결과 |
|---|---|
| 이메일/비밀번호 로그인 | 실제 Auth에서 인증 후 원래 요청한 지난 모임으로 진입 |
| 잘못된 비밀번호 | 인증 거절, 보호된 화면으로 진입하지 않음 |
| 세션 갱신 | refresh token으로 새 세션을 발급받고 같은 시험 사용자임을 확인 |
| 페이지 새로고침 | 로그인 상태 및 기존 자료 화면 유지 |
| 로그아웃 | 로그인 화면으로 이동, 보호된 자료 화면 재진입 시 로그인 요구 |
| 역할별 진입 | 관리자·멤버는 정상 진입, 대기는 `/pending`, 미가입은 `/onboarding` |
| 이전 그룹 URL | 보존한 그룹/일정 ID의 새 주소로 이동 |
| 저장소 HTTP 다운로드 | 기존 14개 파일 모두 실제 Storage HTTP 응답의 SHA-256 일치 |
| 화면에서 자료 클릭 | 자료가 있는 기존 모임 6개 모두 원래 책 제목·파일명·바이트 일치 |

파일 URL을 담은 원래 DB 행은 수정하지 않았다. 테스트 브라우저가 기존 운영 Storage URL로 이동하려 할 때만 해당 요청을 별도 로컬 Storage로 전달했다. 이렇게 내려받은 파일은 실제 로컬 Storage HTTP 응답이며, 클릭·다운로드 이벤트·한글 파일명·바이트를 검증했다. 운영 Storage로 실제 요청을 보내지 않았다.

## 원래 데이터 보존

- 복원한 원래 23개 Auth 계정과 identity를 포함한 기존 행이 검증 전후 일치했다. 기존 비밀번호 해시·인증 식별 정보를 그대로 유지했다.
- 기존 멤버 13명, 일정 11개, 질문 67개, 참석 92개, 평 4개, 초대 2개와 프로필의 모든 필드를 비교했다. 시험 계정의 새 프로필·멤버십만 따로 구분했다.
- 원본 보관 스키마의 모든 행과 Storage 객체·버킷·경로·파일 메타데이터를 대조했다. 기존 모임 데이터나 파일 객체가 추가/변경/삭제되지 않았다.
- Auth 로그인으로 생기는 새 세션·갱신 토큰 등은 새 시험 계정의 로컬 검증 결과다. 원래 인증 테이블의 기존 행은 모두 유지됐다.
- 실제 사용 중인 로컬 DB 17개 테이블의 전후 비교도 통과했다. 원본 운영 dump와 생성 당시 manifest도 동일했다.

로컬 Storage 기동 시 `storage.migrations`의 SQL 파일 해시 **1건**이 다시 계산됐다. 해당 내부 관리 테이블의 ID·이름·실행 시각 등 나머지 모든 필드와 건수 80개는 동일했다. 이를 사용자/파일 기록 변경과 섞지 않고 명시적으로 기록했다. 다른 메타데이터 변화나 행 누락은 검증 실패로 처리한다. 원래 백업은 변경하지 않았다.

## 분리 방식과 증거

- 검증 DB와 Auth/REST/Storage 4개 컨테이너를 새로운 `--internal` Docker 네트워크에 배치했다. 이 컨테이너들은 외부 통신 경로와 공개 포트가 없다.
- 호스트의 loopback 게이트웨이만 브라우저에 열었다. 게이트웨이는 Docker exec의 stdin/stdout 전달을 통해 내부의 실제 HTTP 서비스와 통신했다.
- 앱은 별도 디렉터리·별도 포트에서 실행하고, 새 로컬 전용 JWT 키와 API URL을 사용했다. 기존 `.env.local`과 실행 중인 앱은 바꾸지 않았다.
- 테스트 앱의 외부 fetch/socket 및 브라우저의 외부 요청을 차단했다. 외부 메일 발송·Google OAuth를 끄고 Auth의 오래된 데이터 정리 작업도 비활성화했다.
- 검증에 만든 앱 서버·게이트웨이·컨테이너·네트워크는 정리했다.

최종 원시 보고서: `.local-backups/local-service-flow-20261108T100907061916Z/verification-report.json`. 계정 정보·인증 토큰·시험용 키·로그·복원 DB 스냅샷은 Git 제외 및 비공개 파일 권한으로 보관한다. Git에는 검증 도구·테스트·요약 문서만 포함한다.

## 남은 검증

이메일/비밀번호 인증은 **새 시험 계정**으로 실제 Auth·앱 흐름을 실행한 결과다. 기존 계정은 ID·비밀번호 해시·identity 등 모든 인증 정보의 보존을 비교했으며, 실제 회원의 비밀번호를 입력하거나 재설정하지 않았다.

Google 계정 소유자의 실제 외부 인증·동의 화면은 아직 검증하지 않았다. 운영 관리자 실행 권한 확인, 배포 환경 분리, 외부 쓰기 차단 검증, 쓰기 중단 후 최종 DB/파일 백업도 운영 반영 전에 남아 있다. 운영 DB와 배포는 계속 보류한다.

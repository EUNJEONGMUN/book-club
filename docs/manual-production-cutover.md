## 수동 DB 경로

`scripts/manual-cutover.py`는 기본 오프라인이며, 변경 SQL을 네트워크로 전송하지 않는다. 준비 명령은 기존 실행·릴리스에 묶인 SQL 파일만 만든다. 관찰 명령은 관리 API에 `read_only:true`인 SELECT만 보내며 역할도 `supabase_read_only_user`다. 이 역할의 BYPASSRLS·pg_read_all_data 읽기 권한은 조회로 확인했고 새 권한을 부여하지 않았다.

수동 실행 파일은 기존 엔진의 **postgres 실행자·DB·실행ID·릴리스·단계·백업/복원 해시 조건을 유지**한다. 관찰자의 역할을 실행자로 위장하지 않는다. 읽기 관찰이 끝나 실제 변경이 필요한 지점에서는 SQL 파일을 내보내고 멈춘다. 소유자가 그 파일을 psql로 직접 실행한다.

- `01-freeze.sql`: 대상/이력·기존 전환 상태/의존성·진행 업로드를 검사한 뒤 제어 행 생성과 전체 임시 차단을 **한 트랜잭션**에서 설치한다. 누락/실패 시 전체 롤백한다.
- `cancel-before-migration.sql`: 원래 구조/클럽/이력과 실행 단계를 확인한 뒤 전환 전에만 임시 차단을 제거한다. 기존 기록을 복원하거나 덮어쓰지 않는다.
- 02/03/04: 검증한 원래 SQL 해시, 실행 순서와 서버의 `backup_verified` 해시를 요구한다. 실행 직전에도 차단 함수·트리거·API 권한·업로드 상태를 검사한다.
- 백업 승인: 소유자가 만든 full/public 아카이브를 같은 차단 구간의 행·정책·파일과 묶는다. 아카이브 안 제어 행의 실행/릴리스/차단 시각도 확인하고 실제 격리 복원을 수행한 뒤에만 승인 SQL을 내보낸다.
- 보존 비교·복구·재개: 기존 Core 검사를 재사용한다. 복구는 먼저 실패 상태도 보존하고 현재 단계와 일치하는 원래 public 사본을 복원한다. Auth/Storage 행·물리 파일은 덮어쓰지 않는다. 확인 전 `recovering`에서는 재개를 거절한다.

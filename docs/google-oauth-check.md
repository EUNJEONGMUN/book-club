# Google 로그인 로컬 확인 — 2026-11-08

현재 상태: **계정 소유자가 실제 Google 인증을 완료해 로컬 앱의 인증된 이름 등록 화면에 도착한 것을 확인했다.** Google 제공자 인증 → 로컬 Supabase 반환 → 앱 콜백/세션까지 확인했다. 새 로컬 프로필 이름 등록과 모임 가입 승인은 제출하지 않았다. 운영 DB/인증 설정·Google 콘솔 설정·배포는 변경하지 않았다.

## 확인한 로컬 설정

- 앱: `http://localhost:3000`
- 로컬 Supabase Auth: `http://127.0.0.1:54321/auth/v1`
- Google 제공자 반환 주소: `http://127.0.0.1:54321/auth/v1/callback`
- 앱의 로그인 완료 처리: `/auth/callback`
- Google 제공자 활성화와 client ID/secret 존재를 확인했다. ID는 Google 형식이며 임시 예시 값이 아니었다. 실제 식별자·비밀키는 출력하거나 문서에 저장하지 않았다.
- 사용자가 실제 계정 선택/동의를 진행한 뒤 앱으로 돌아왔고, 신규 로컬 Google identity와 인증된 이름 입력 화면을 확인했다. 로컬 반환 URI를 통한 실제 인증/콜백이 동작했다.

꺼져 있던 로컬 앱을 다시 실행했고, 원래 로컬 DB는 초기화하지 않았다. 사용자에게 아래 화면에서 직접 계정 선택·동의를 진행하도록 안내했다. 비밀번호·인증 코드는 채팅으로 받지 않는다.

`http://localhost:3000/login?next=%2Fmeetings%2F20000000-0000-0000-0000-000000000002`

## 점검 중 보완한 동작

기존 콜백은 코드 교환 결과의 오류를 확인하지 않고 목적지로 이동했다. 이제 인증 실패·네트워크 오류·인증 코드 누락 시 로그인으로 돌려보내고, 원래 열려던 내부 주소를 유지한다. Google 계정 선택/동의 취소도 로그인 화면에서 안내한다. 제공자가 반환한 원시 오류·인증 코드는 안내 URL이나 메시지에 넣지 않는다.

이동 주소의 탭/줄바꿈 등 제어문자가 URL 해석 과정에서 제거되면 외부 도메인 주소로 바뀔 수 있는 문제도 테스트로 재현하고 차단했다. 정상 내부 경로·쿼리·한글 주소는 유지한다.

- 단위 테스트 전체 66개 통과. 성공 후 모임 주소 유지, 실패/취소/예외/코드 누락, 외부 이동 차단, Google 버튼의 로컬 콜백·목적지 전달, 재시도 안내를 포함한다.
- 타입 검사 통과.
- 현재 소스의 별도 복사본에서 `next build --webpack` 통과. 실제 사용 중인 로컬 앱을 중단하거나 그 빌드 폴더를 덮어쓰지 않았고, 검증용 복사본은 정리했다.
- `.local-backups/google-oauth-check-20261108T103306740995Z/`에 전후 로컬 레코드 스냅샷·보존 확인서·빌드 로그를 비공개로 보관했다. 실제 Google 로그인 후 새 로컬 Auth 계정 1개와 Google identity 1개가 생성됐다. 새 계정의 로컬 프로필·멤버십은 아직 없다. 원래 모임/회원/파일/보관 기록과 기존 계정 ID·비밀번호 해시·인증 제공자 식별자는 모두 유지됐다.
- 실제 도착 주소는 `/signup`이었다. 화면의 이름 입력란과 “로그인되었어요” 안내를 확인했다. 이 화면은 인증은 됐지만 프로필이 없을 때만 반환하는 분기와 일치했다. 사용자 이메일·Google subject·인증 코드는 출력하거나 문서에 저장하지 않았다.
- 새 로컬 Google identity의 제공자 식별자가 보관된 운영 데이터의 기존 관리자 identity와 일치했고, 해당 운영 프로필과 관리자 멤버십도 백업에 남아 있는 것을 확인했다. 원래 운영 Auth 사용자 ID와 새로 만든 로컬 Auth 사용자 ID는 같은 것으로 취급하지 않는다. 현재 로컬 앱은 시드 DB를 사용하며, 운영 데이터를 복원했던 검증 DB와 구분한다.
- 원래 운영 dump의 SHA-256도 동일했다. 실제 인증 후 확인서는 `google-login-preservation.json`에 기록했다.
- DB 스키마·RLS·회원 승인·기존 비밀번호는 변경하지 않았다. 이전 운영 백업과 격리 복원 증거도 유지했다.

## 확인 범위와 남은 사항

1. 실제 Google 계정 선택/동의 및 앱 반환·세션·이름 입력 화면까지 확인했다. 기존 운영 관리자 정보가 보관되어 있다는 것도 로컬 백업에서 확인했다.
2. 새로 생성된 로컬 본인 계정의 이름 입력·가입 신청·승인은 수행하지 않았다. 추가 진행은 사용자의 의사를 따르며, 새 계정도 임의 삭제하지 않는다.
3. 실제 Google 계정으로 현재 시드 DB의 모임 화면을 이용하는 단계는 프로필·가입 상태 설정이 선행되어야 한다. 원래 운영 멤버가 전환 후 조회할 데이터와 권한은 별도 복원 보존 검증(226개) 및 실제 로컬 서비스 검증(18개 흐름/92개 보존)에서 확인한 범위를 유지한다.
4. 운영 관리자 실행 권한, 배포 환경 분리, 외부 쓰기 차단, 쓰기 중단 후 최종 백업은 계속 남아 있다. 이번 확인에서 운영 DB에는 연결하지 않았다.

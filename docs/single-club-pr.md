# PR 본문 초안

부글부글 하나만 사용하는 서비스에서 그룹 선택·생성·삭제 흐름을 제거하고, `/meetings`, `/members`, `/more` 중심으로 화면과 서버 처리를 전환한다. 기존 부글부글 URL은 새 주소로 연결하며 다른 모임 ID는 거절한다.

DB 전환은 기존 ID·계정·멤버 역할·가입 시각·일정·질문·참석·평·초대코드·파일 경로를 유지한다. `club_settings`, `members`, `invites`로 전환하고 원래 다중 모임 테이블과 변경 전 프로필·일정은 비공개 `legacy_multiclub`에 보관한다. 대상 UUID, 관리자 존재, 다른 모임의 일정 여부와 데이터 일치를 검사하며 실패한 SQL은 해당 트랜잭션을 롤백한다.

과거 참석 변경 제한, 발제자별 파일 쓰기 권한, 보관본 쓰기 거절과 계정 삭제로부터의 독립성을 DB에서 검증한다. 구 앱에도 적용 가능한 점검 모드 패치와 전환·복구 절차, 조회 전용 운영 사전 복사 도구를 함께 제공한다.

## 검증

- 단위 39개, 로컬 PostgreSQL/RLS 통합 60개, 조회 전용 브라우저 4개 통과.
- 타입 검사와 프로덕션 빌드 통과.
- 대표 데이터 복원·전환 리허설 19개 검사 통과. 실제 PDF 바이트·한글 파일명·공개/비공개/익명 평·OAuth identity·초대 상태 등을 확인.
- 현재·보관 17개 로컬 테이블의 기존 기록과 계정 식별·인증 정보가 전후 동일함을 확인.
- 실제 운영 아카이브를 격리 복원하고 전체 레코드·권한·시퀀스·파일·전환 보존 226개 검사 통과.
- 별도 로컬 Auth/REST/Storage와 임시 계정으로 실제 로그인·세션 갱신·역할별 이동·자료 다운로드 18개 흐름 및 기존 데이터 보존 92개 검사 통과. 파일 14개 HTTP 해시와 기존 모임 6개 클릭 다운로드의 바이트·파일명 확인.
- 운영은 읽기 전용 조회·사전 복사만 수행. 운영 DB 전환과 배포는 미실행.

## 운영 반영 조건

**이 PR을 병합/배포하면 안 되는 조건이 남아 있다.** 운영 역할·소유권·권한 검토, 운영 연결을 차단한 Preview 구성, 외부 쓰기 차단 검증과 중단 시점 최종 백업이 필요하다. 실제 Google 인증 → 로컬 앱 세션/이름 입력 화면도 확인했고 기존 계정·관리자 정보 보존을 대조했다. 새 로컬 프로필 등록/승인은 제출하지 않았다. 현재 확보한 아카이브·파일의 격리 복원과 로컬 이메일 인증·다운로드는 검증했지만, 새 앱은 기존 운영 스키마와 호환되지 않는다.

운영 이력 대조 기준 미적용 SQL은 02·03·04이며 순서를 유지한다. 앱·DB·파일의 최종 백업과 복구 절차를 확보한 뒤 별도 승인으로 진행한다. 쓰기 재개 후에는 이전 백업으로 단순 덮어쓰지 않는다.
